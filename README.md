# MIS API - Тестовое задание

Мини-проект медицинской информационной системы (МИС), реализованный на .NET 10 с использованием .NET Aspire, ASP.NET Core и PostgreSQL. 

## 1. Технологический стек
*   **Платформа:** .NET 10, ASP.NET Core Web API
*   **Оркестрация:** .NET Aspire (AppHost, ServiceDefaults)
*   **База данных:** PostgreSQL (развертывание через Docker)
*   **ORM:** Entity Framework Core 10 (Npgsql)
*   **Документация:** Swagger / OpenAPI
*   **Генерация данных:** Bogus (скрипт написан с использованием ИИ)

## 2. Архитектура решения
Проект реализован по паттерну Clean Architecture:
*   `Domain` — сущности предметной области (Patient, Practitioner, Condition, Encounter, Observation), Value Objects (CodeableConcept) и перечисления. Не имеет внешних зависимостей.
*   `Application` — бизнес-логика (Сервисы), контракты (DTO), интерфейсы репозиториев, кастомные исключения.
*   `Infrastructure` — реализация работы с БД (DbContext, конфигурации EF Core, репозитории, миграции, сидер данных).
*   `Api` — контроллеры, глобальный Middleware для обработки исключений, настройка DI и Swagger.
*   `AppHost` — оркестратор Aspire для управления API и контейнером с БД.

## 3. Модель данных
Модель спроектирована с учетом специфики МИС и подходов стандарта HL7 FHIR:
*   **Patient** — карточка пациента (ФИО, контакты, адреса, идентификаторы, семейное положение).
*   **Practitioner** — врач (ФИО, лицензии, квалификации).
*   **Encounter** — прием/визит (связующее звено между пациентом и врачом).
*   **Condition** — диагноз (привязан к пациенту, врачу и приему).
*   **Observation** — замеры (температура, давление), привязанные к приему.
*   **CodeableConcept** — универсальный тип для кодирования данных (МКБ-10, специальности), реализован через `OwnsOne`.

## 4. Реализованный функционал
**Вывод данных (REST API):**
*   `GET /api/patients` — список всех пациентов.
*   `GET /api/patients/{id}` — полная карточка пациента (с историей приемов, диагнозами и замерами).
*   `GET /api/practitioners/by-specialty?code={code}` — поиск врачей по коду специальности.
*   `GET /api/practitioners` — список всех врачей.
*   `GET /api/practitioners/specialties` — справочник уникальных специальностей.
*   `GET /api/conditions` — общий список болезней.

**Бизнес-логика и оптимизация:**
*   Оптимизация запросов: решена проблема N+1 при загрузке замеров (использование `ToLookup` и агрегирующего запроса).
*   Логирование: использование `ILogger` на всех слоях приложения.
*   Защита данных: безопасный маппинг DTO с использованием null-conditional операторов.

**Обработка ошибок:**
*   Глобальный `ExceptionHandlingMiddleware`.
*   Кастомное исключение `NotFoundException` (транслируется в HTTP 404 с JSON-ответом).
*   Встроенная валидация ASP.NET Core (транслируется в HTTP 400 в формате Problem Details).

**Работа с БД:**
*   Настроен механизм миграций EF Core.
*   Реализован автоматический сидинг базы (30 пациентов, 10 врачей, 40 приемов, 50 диагнозов, 60 замеров).
*   Настроено приведение дат к UTC для корректной работы с типом `timestamp with time zone` в PostgreSQL.

## 5. Инструкция по запуску

**Требования:**
*   .NET 10 SDK.
*   Docker Desktop (с включенным WSL 2).

**Шаги:**
1. Клонировать репозиторий.
2. Открыть решение (`.sln`) в Visual Studio.
3. Убедиться, что проект `AppHost` выбран как Startup Project.
4. Нажать `F5`.
5. Откроется Aspire Dashboard. Дождаться статуса `Running` у контейнера `postgres` и проекта `api`.
6. В Aspire Dashboard скопировать URL API (например, `https://localhost:7273`).
7. Перейти в Swagger UI по адресу: `{URL_API}/info`.

## 6. Примечание
Генератор тестовых данных (`DataGenerator.cs`) написан с использованием инструментов Искусственного Интеллекта для ускорения разработки. Скрипт использует библиотеку `Bogus` для создания связанных тестовых сущностей.
